summary: Password security, session protection, CSRF protection and why “Access denied” appears.
=== what
Security features that work in the background:

- **Password security**: passwords are stored only as a strong one-way hash (Argon2id). Nobody, including administrators, can read them. A password policy blocks weak passwords.
- **Generic error messages**: sign-in and reset messages never reveal whether an email address has an account.
- **Session protection**: secure, HttpOnly cookies, a new session ID at every sign-in, inactivity and absolute time limits, and sign-out when the account changes.
- **CSRF protection**: every form carries a hidden security token. A form submitted from another website, or a page left open across a sign-out, is rejected.
- **Server-side authorisation**: every page and action is checked on the server. Hiding a button is never the only protection.
- **Audit trail**: important actions are recorded with who, what, when and from which IP address.
=== why
The ERP holds partners' personal and financial data. These controls keep it confidential and make every change traceable.
=== who
Everyone benefits; there is nothing to switch on.
=== step: Recognise “Access denied” | access-denied
If you open an address you are not allowed to use, the server returns **Access denied**. Nothing is changed. Ask your administrator if you need access.
=== step: Handle an expired form
If a form says the page expired, reload the page and submit again. This happens when the security token is no longer valid, for example after signing out in another tab.
=== example: A crafted request is refused
A user with view-only access tries to submit an edit form by typing the address directly. The server checks the permission, refuses with **Access denied**, records the attempt in the audit trail, and changes nothing.
=== result
You know which messages are security protections rather than errors.
=== notes
- Never store banking passwords, PINs or OTPs anywhere in the ERP. Payment references are fine; secrets are not.
- Records outside your data visibility answer **Page not found**, so record numbers cannot be probed.
=== mistakes
- Treating “Access denied” as a fault and retrying. It is a permission decision.
=== faq: Why “Page not found” for a record I know exists?
The record is outside your data visibility. The ERP deliberately does not confirm it exists.
